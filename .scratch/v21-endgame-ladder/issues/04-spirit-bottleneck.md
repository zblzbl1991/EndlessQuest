## Question

如何让"灵气 → 修为"生产链耦合在全程成立（而非只在第一小时），同时不违反"低操作高反馈"——瓶颈真实存在但可通过经营解决？（map 决策 3）

### 背景数据

现状：修炼耗灵气常数 `SPIRIT_COST_PER_SECOND = 2/秒/弟子`，中后期永不触发 `spiritScale < 1`，聚灵阵失去存在意义。

### 范围

1. **消耗曲线**（`CultivationEngine`）：每弟子灵气消耗 = `2 × 2^realmIndex`（境界每进一层 ×2，略高于修为速率的逐境增速 ×1.67 → 单位修为的灵气成本逐境温和上升 1.2~2×）。
2. **供给曲线联动**（依赖工单 03）：聚灵阵 `3 × 1.10^lv` 指数产出 + Milestone 倍率（Lv10 ×2 / Lv50 ×3 / Lv250 每级+1% 修炼速度等）是对冲手段；校准目标：**"正常建设水平"下每境界 spiritRatio ≥ 0.9，疏于建设时在 0.5~0.9 区间产生可感知的修为缩水（教学时刻保留）**。
3. **语义保留**：`spiritScale = min(1, 可用/需求)` 缩水机制不变；灵气不足的 UI 提示与离线报告归因（"修为缩水：灵气供给 xx%"）保留/补齐。
4. **旧档兼容**：境界已有的弟子消耗按当前境界即时生效（无迁移）。
5. **模拟校准**：`simulate-pacing.ts` 输出逐境界 spiritRatio 与"建设跟进所需聚灵阵等级"，断言全程无死锁（不存在灵气收入数学上追不上消耗的境界）。

### 不做

- 灵气上限公式重构（跟随既有 caps 管线 + Milestone 放宽）；新增灵气存储建筑。

## Acceptance

1. 单测：消耗随境界 ×2、spiritScale 缩水路径、Milestone 对冲生效。
2. 模拟：逐境界 spiritRatio 表 exit 0（正常建设 ≥0.9；疏于建设 <0.9 但可恢复；无死锁境界）。
3. `npm test` 全量绿。
